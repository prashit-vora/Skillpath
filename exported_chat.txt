## How a Framer code component works

A Framer code component is an ordinary React component with some Framer-specific additions.

```tsx
export function CourseGrid() {
  return <section>...</section>
}
```

When you paste this into Framer, `CourseGrid` appears in Framer’s Assets panel. You can drag it onto the visual page like any other layer.

The Framer-specific import is:

```tsx
import { addPropertyControls, ControlType } from "framer"
```

This lets us create editable settings in Framer’s right-hand panel.

## 1. Course data types

The `Course` interface describes the data expected from the API:

```tsx
export interface Course {
  courseName: string
  courseCode: string
  description: string
  mainCategory: string
  pricePaise: number
  priceUsdCents: number
  refundable: boolean
  // ...
}
```

TypeScript uses this to catch mistakes while developing. For example, it knows that `pricePaise` must be a number.

The supported countries are limited to:

```tsx
export type CountryCode = "IN" | "US"
```

This prevents us from accidentally handling an unknown country as India or the US.

## 2. Validating the API response

TypeScript cannot guarantee that an external API returns valid data. That is why we check the response at runtime:

```tsx
export function parseCourses(value: unknown): Course[] {
  if (!Array.isArray(value) || !value.every(isCourse)) {
    throw new Error("Unexpected course response")
  }

  return value
}
```

This checks:

- The response is an array
- Every item contains the required fields
- Prices are numbers
- `refundable` is a boolean

Country data is checked similarly:

```tsx
if (countryCode !== "IN" && countryCode !== "US") {
  throw new Error("Unsupported country code")
}
```

These errors are used internally. They are never dumped onto the page.

## 3. Fetching the API

The reusable request function is:

```tsx
async function requestJson(path: string, signal: AbortSignal) {
  const response = await fetch(`${API_BASE_URL}${path}`, {
    method: "GET",
    headers: { Accept: "application/json" },
    signal,
  })

  if (!response.ok) {
    throw new Error(`Request failed with ${response.status}`)
  }

  return response.json()
}
```

Important details:

- It explicitly uses `GET`
- It checks `response.ok`
- A 404 or 500 becomes a controlled failure
- `AbortSignal` lets us cancel the request if the component disappears

We then have separate functions for each endpoint:

```tsx
fetchCourses(controller.signal)
fetchCountry(controller.signal)
```

## 4. Why `Promise.allSettled` is important

The two requests run together:

```tsx
const [courseResult, countryResult] = await Promise.allSettled([
  fetchCourses(controller.signal),
  fetchCountry(controller.signal),
])
```

`Promise.allSettled` waits for both requests and tells us which succeeded or failed.

If we used `Promise.all`, one failed country request would reject everything—even if the courses loaded successfully.

Our behaviour is:

| Course request | Country request | Result |
|---|---|---|
| Fails | Anything | Error message and retry |
| Succeeds with zero courses | Anything | Empty state |
| Succeeds | Succeeds | Cards with correct prices |
| Succeeds | Fails | Cards with “Price unavailable” |

We intentionally do not assume the user is Indian when country detection fails. Guessing could display the wrong price.

## 5. Component state

The screen can be in one of three code-level states:

```tsx
type ViewState =
  | { status: "loading" }
  | { status: "error" }
  | {
      status: "ready"
      courses: Course[]
      countryCode: CountryCode | null
    }
```

The assignment’s four visible situations are represented as:

- `loading`
- `error`
- `ready` with an empty course array
- `ready` with courses

`countryCode: null` means country detection failed.

React stores this with:

```tsx
const [viewState, setViewState] = useState<ViewState>({
  status: "loading",
})
```

When `setViewState` is called, React automatically renders the appropriate interface.

## 6. Loading the data with `useEffect`

```tsx
useEffect(() => {
  const controller = new AbortController()

  async function loadCourses() {
    // Fetch and update state
  }

  void loadCourses()

  return () => controller.abort()
}, [attempt])
```

`useEffect` runs after the component is placed on the page.

The `[attempt]` dependency means it runs again whenever the retry counter changes:

```tsx
const retry = () => {
  setAttempt((currentAttempt) => currentAttempt + 1)
}
```

The retry button therefore does not reload the whole website. It simply repeats the API calls.

`controller.abort()` prevents an old request from attempting to update a component that is no longer on the page.

## 7. Correct currency conversion

The API sends prices in minor units:

- 100 paise = ₹1
- 100 cents = $1

Therefore:

```tsx
const amount = minorUnits / 100
```

Then the browser’s currency formatter handles the symbol and separators:

```tsx
new Intl.NumberFormat("en-IN", {
  style: "currency",
  currency: "INR",
}).format(amount)
```

Our expected results are:

```text
199900 paise → ₹1,999
3999 cents   → $39.99
```

This is also protected by automated tests.

## 8. Rendering course cards

Courses are converted into cards using `map`:

```tsx
{viewState.courses.map((course, index) => (
  <article key={course.courseCode}>
    ...
  </article>
))}
```

This means the grid works with 5, 7, 8, 10, or any other number of courses.

`courseCode` is used as the React key because it should uniquely identify a course.

Each card displays:

- `mainCategory`
- `courseName`
- `description`
- Converted price
- Refundable badge when applicable

The badge is conditional:

```tsx
{course.refundable && (
  <span className="spc-badge">Refundable</span>
)}
```

If `refundable` is false, React renders nothing there.

## 9. Two-line descriptions

The relevant styling is:

```css
display: -webkit-box;
overflow: hidden;
-webkit-box-orient: vertical;
-webkit-line-clamp: 2;
```

This visually cuts longer descriptions off after two lines instead of letting differently sized descriptions make the cards uneven.

## 10. Responsive columns

The default desktop grid uses three columns:

```css
grid-template-columns: repeat(3, minmax(0, 1fr));
```

Tablet changes it to two:

```css
@media (max-width: 960px) {
  .spc-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}
```

Mobile changes it to one:

```css
@media (max-width: 620px) {
  .spc-grid {
    grid-template-columns: 1fr;
  }
}
```

The layout does not care whether the final row is complete.

## 11. Framer property controls

These lines create exactly two settings in Framer:

```tsx
addPropertyControls(CourseGrid, {
  heading: {
    type: ControlType.String,
    title: "Heading",
  },
  accentColor: {
    type: ControlType.Color,
    title: "Accent",
  },
})
```

A non-programmer can then:

- Change the heading text
- Pick a different accent colour

The selected values arrive as normal React properties:

```tsx
export function CourseGrid({
  heading = "Courses for your next move",
  accentColor = "#d9ff57",
}: CourseGridProps)
```

The accent becomes a CSS variable:

```tsx
"--spc-accent": accentColor
```

That variable controls badges, retry buttons, and status icons.

## 12. Framer layout annotations

These comments tell Framer how the component should be sized:

```tsx
/**
 * @framerSupportedLayoutWidth any
 * @framerSupportedLayoutHeight auto
 */
```

- Width can be fixed or responsive
- Height should grow automatically to contain the returned cards

## 13. Why the styles are inside the component

The component includes:

```tsx
<style>{courseGridStyles}</style>
```

That makes `CourseGrid.tsx` self-contained. You can paste one file into Framer without also needing to upload a separate CSS file.

The large [styles.css](/home/tardigrade/Skillpath/src/styles.css) file only styles the local hero and footer. It does not need to be copied into the Framer code component.

## 14. What is `framer-shim.ts`?

The real Framer editor supplies functions such as `addPropertyControls`. Framer’s npm package only supplies their TypeScript definitions, not a normal runtime implementation.

Our local Vite preview would therefore fail without [framer-shim.ts](/home/tardigrade/Skillpath/src/framer-shim.ts).

Locally, it makes property registration do nothing:

```tsx
export function addPropertyControls() {
  // No operation locally
}
```

Inside the actual Framer editor, this shim is not copied or used. Framer supplies the real function, and the controls appear in its interface.

The central idea is: React fetches and displays the live data, while Framer treats that React component as a draggable, visually configurable page element.
